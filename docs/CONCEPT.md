# プロジェクトコンセプト

## 一行で

**家系ラーメンの「誰が誰に教わったか」を、出典を辿れる形で残し、誰でも読めて、誰でも直せる公共の系図にする。**

---

## なぜやるのか

1974年、吉村実氏が新杉田で吉村家を開いた。そこから暖簾は、修行と独立の連鎖で増えていった。本牧家が出て、六角家が出て、その先に何十という店が続いた。

けれど**その繋がりは、どこにもまとまって置かれていない。** 店主の口から弟子へ、常連の記憶へ、個人ブログの数行へ、閉店を惜しむ SNS の投稿へ。断片として散らばったまま、時間とともに薄れていく。

このリポジトリが収録している27店のうち、すでに数店は「閉店」「本店閉店」だ。六角家の本店は2017年に閉じた。店が閉まるとき、失われるのは味だけではない。**その店が誰から教わり、誰に教えたかという線も一緒に消える。**

地図アプリは「いまどこにあるか」を教えてくれる。レビューサイトは「評判がどうか」を教えてくれる。**「どこから来たか」を教えてくれるものが、まだない。** その空白を埋めるのがこのプロジェクトだ。

## 何を作るのか

作るものは二つある。そして**順番が重要**だ。

### 1. 系譜データ（本体）

`src/data/shops.ts` に置かれた、店と師弟関係の記録。屋号・所在地・創業年・師匠・系統・確度・解説。**これがこのプロジェクトの資産で、価値のほぼ全部**である。

データは以下を守る。

- **事実と推測を混ぜない。** 系譜上の位置づけに諸説ある店は `edge: "disputed"`（点線）、創業年が概算なら `approx: true`（「頃」表記）。断定できないことは、断定できないと画面に書く。
- **公開情報のみ。** 出典を示せない話は載せない。関係者しか知らない事情や、店主の私的な情報は扱わない。
- **裏取りできた店だけ入れる。** 「たぶんあの系統」で 1 軒足すと、その誤りは系図全体の信頼を削る。

### 2. 系図アプリ（データの読み方）

データを、**縦書きの屋号が並ぶ伝統的な系図**として一目で読めるようにしたもの。ドラッグで辿り、屋号に触れれば吉村家までの経路が浮かび上がり、年スライダーを動かせば暖簾が広がっていく様子が見える。

アプリは静的サイト（`output: 'export'`）として出力される。サーバーもデータベースもアカウントも持たない。**データが消えない限り、このプロジェクトはどこにでも置き直せる。**

## 誰のために

| その人 | 欲しいもの | いま渡せているか |
|---|---|---|
| 家系を食べ歩く人 | 「この店の師匠はどこか」「兄弟弟子はどこか」 | ○ 詳細パネルで辿れる |
| 家系を知らない初心者 | 「直系って何？」「系統の違いは？」 | △ 凡例と解説はあるが、入口が硬い |
| 記録を残したい人 | 失われる前に書き留める場所 | ○ Issue / PR で足せる |
| 関東以外の人 | 自分の街の店の系譜 | ✗ 現在は3都県のみ（[#2](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/2)） |
| データを使いたい人 | 二次利用できる系譜データ | ○ CC BY-SA 4.0 で公開 |

## 大切にする5つのこと

### 1. 事実と推測を分ける

わからないことを「わからない」と表示するのは、後退ではなく品質だ。点線（諸説あり）と「頃」（概算）は、このプロジェクトの誠実さそのものである。**確信のない情報を断定調で書くくらいなら、載せないほうがいい。**

### 2. データが主、アプリは従

機能を増やすより、1軒の系譜を正確に直すほうが価値が高い。フレームワークは10年後には変わっているだろうが、**「武道家は武蔵家から出た」という事実は変わらない。**

### 3. コードを書けなくても直せる

誤りを知っている人が、必ずしも Git を使えるとは限らない。**このプロジェクトでいちばん貴重なのは「その店に通っていた人の記憶」**であって、プルリクエストの作法ではない。Issue に一行書くだけで直せる導線を、常に最短に保つ。

### 4. 店に順位をつけない

味の優劣、ランキング、点数、「おすすめ」——**やらない。** 系譜は事実の記録であって、評価ではない。掲載の順序や可否が金銭で動かないこと（広告・アフィリエイトを置かないこと）も、このデータが信用される条件だと考えている。

載せる特徴は「ライス無料」「うずらの卵」のような**公知で客観的な事実**に限る。「濃厚」「あっさり」は人によって違う。

### 5. 決めごとは公開の場で

設計も方針も Issue で決める。議論の経緯が残っていれば、後から来た人が「なぜこうなっているか」を辿れる。**閉じた場所で決まったことは、賛同のしようがない。**

## やらないこと

やらないことを先に決めておくと、判断が速くなる。

- **ランキング・点数・口コミ** — レビューサイトの仕事であり、系図の仕事ではない
- **店の批判** — 閉店の理由や経営の内情に踏み込まない
- **非公開情報** — 店主の私生活、取引先、係争中の事柄
- **味の優劣の断定** — 主観を事実として記述しない
- **広告・アフィリエイト** — 掲載が金銭で動く疑いを持たれた時点で、系譜データの価値は失われる
- **ユーザーアカウント・ログイン** — 静的サイトのまま保つ。訪問記録を残す機能は端末内（`localStorage`）に閉じる（[#15](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/15)）
- **網羅性の追求そのもの** — 裏取りできない店を数合わせで足さない。**27軒の正確な系図は、200軒の怪しい系図より価値がある**

## うまくいっているかの見かた

PV は目的ではない。見るのはこの4つ。

1. **外部からの修正・追加が入っているか** — 作者以外が「ここが違う」と言える状態かどうか。これが 0 のままなら、導線が悪いということ
2. **出典を辿れる店の割合** — いま系譜の根拠は Issue / PR の議論に残っているだけで、データ本体には持っていない。`sources` フィールドとして持たせるのが次の課題
3. **「自分の街の店が出てこない」が減っているか** — [#2](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/2)（東海・関西）、その先の地方
4. **誤りがデプロイ前に止まるか** — [#20](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/20)（テスト戦略）。データが壊れて白画面になる経路を塞ぐ

## 参加のしかた

**このプロジェクトが本当に必要としているのは、コードよりも「その店を知っている人」です。**

- 系譜の誤り・抜けを見つけた → [データの修正・追加 Issue](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/new?template=data-correction.yml)（コード不要・1分）
- 動かない・見づらい → [不具合の報告](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/new?template=bug.yml)
- こうなったら面白い → [アイデアの提案](https://github.com/miyata09x0084/iekei-ramen-family-tree/issues/new?template=idea.yml)
- 自分で直したい → [CONTRIBUTING.md](../CONTRIBUTING.md)

進め方の約束や、議論の作法は [行動規範](../CODE_OF_CONDUCT.md) にまとめています。
