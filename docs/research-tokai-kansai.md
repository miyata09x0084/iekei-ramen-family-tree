# 東海・関西の家系 系譜調査（issue #2 の第1工程）

issue #2「東海・関西の家系を収録し、地方の人も系譜を辿れるようにする」の進め方1に当たる調査の記録。

**調査日**: 2026-09-21

## この調査の限界（先に読むこと）

作業環境の egress ポリシーにより、一次情報のページを直接開けなかった（`ja.wikipedia.org` / `tabelog.com` / `ramendb.supleks.jp` / `news.yahoo.co.jp` など、試した全ドメインが CONNECT 403）。
したがって**以下はすべて web 検索の結果要約に基づく**。確度は複数クエリで同じ記述が独立に出たかで判定している。

`NODES` に投入する前に、確度「中」以下は一次情報（店の公式サイト・公式 X・開店告知記事）での確認が必要。確度「高」も、住所と開店日は公式の表記に揃えること。

参照した情報源の中には系統の分類を誤っているもの（例: 壱六家を「吉村家の直系店」と書く記事）があった。修行元の事実と、記事が付けた系統ラベルは分けて扱っている。

## 結論：設計判断は (a) でよい

issue #2 で「最初に決めること」としていた論点への答え。

> (a) 系譜が裏取りできた店だけ入れる / (b) 系譜不明の独立店も木の外に置ける枠を用意する

**(a) で足りる。** 東海・関西のいずれにも、既存ノード（王道家・新中野武蔵家・壱六家・侍・六角家）にそのままぶら下がる店が複数見つかった。`parent: null` の受け皿を新設しなくても、地方の人が「自分の街の店 → 吉村家」を辿れる状態にできる。

`d3.stratify` の単一ルート制約（`src/lib/layout.ts:50`）に手を入れる必要はない。

ただし枝を繋ぐために、**関東の未収録ノードを3つ足す必要がある**（下記「関東の中間ノード」）。

## 既存データに対する再検証事項

調査中に、現在の `src/data/shops.ts` と食い違う記述に当たった。issue #2 の本体ではないが、放置すると東海・関西の枝を間違った場所に繋ぐことになる。

1. **武蔵家は2系統ある** — 「**新中野武蔵家**（たかさご家経由、81店超）」と「**吉祥寺武蔵家**（六角家の直弟子、少数展開）」は別系統である、という記述が複数出た。現在のデータは `musashi`（武蔵家 千葉 1997）→ `musashi-nakano`（武蔵家 新中野 2001）と繋いでいるが、系譜資料側は「たかさご家 → 新中野武蔵家」としている。`takasago` は既にデータにある（六角家出身 1998）ので、繋ぎ替えの要否を確認すること。大阪の武蔵家系3店（そらの星・教道家・武双家）の親が変わるため、東海・関西の投入前に決着させる必要がある。

2. **洞くつ家は「吉祥寺武蔵家を共同で開いた後に独立」** — 上記1と関係する。吉祥寺武蔵家自体が未収録。

3. **六角家1994+** — 2024-04-08 に新横浜ラーメン博物館へ再出店（浜松・蔵前家の袴田雄二氏が創業者の指名で担当）。現在の `rokkaku` の note は「本店2017閉店 → 戸塚が継承 → 2025年トツカーナモール移転」まで。ラー博の再出店に触れていない。
