# ADR 0004: 店の外観画像を Google ストリートビューから都度読み込む

- 日付: 2026-10-06
- 状態: 採択

## 背景

#60 で、店を同定できるように全店に外観画像を 1 枚ずつ出すと決めた。条件は「全 28 店に必ず揃う」「無料」「定期作業・返信を生まない（ADR 0001）」「権利が明快」の 4 つ。味の評価にならないよう、どんぶりや店内は扱わない。

全店が関東（神奈川・東京・千葉）にあり、愛知からは自分で撮りに行けない。店の公式発信は無い店が多く、Wikimedia Commons にも家系の店はほぼ無い。利用者からの投稿は審査と返信が生まれる。

## 決定

Google ストリートビュー（Street View Static API）の画像を使う。

- 画像はリポジトリに保存せず、ページを見た人のブラウザが Google から都度読み込む（Google の規約に従う。帰属表示は画像内の透かしと「画像: Google ストリートビュー」のキャプション）
- 店舗データは住所（`exterior.location`）だけを持ち、URL の組み立ては `src/lib/exterior.ts` に集める。住所で地点がずれる店だけ `pano` / `heading` で上書きする
- API キーは `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` としてビルド時に埋め込む。キーには API 制限（Street View Static API のみ）と HTTP リファラー制限を付け、CI には置かない
- 無料枠（月 10,000 リクエスト）を超えたときは画像が出なくなるだけで、ページは壊れない。超過時に課金する判断はしない
- 系図のノードには出さない。系図を 1 回開くたびに 28 リクエスト消費し、月 357 回の閲覧で枠を使い切るため（#61）

## 検討した代替案

- **Mapillary（CC BY-SA の投稿型ストリート画像）**: 画像を保存でき、キーも枠も不要。だが郊外（厚木・柏・千葉）の網羅が保証できず、「必ず揃う」を満たせない
- **屋号の暖簾画像を自前生成**: 100% 揃い権利も明快だが、写真でないので「店を同定する」目的に効かない
- **自分で撮影 / 公式 SNS の埋め込み / CC 画像**: いずれも全店には揃わない。公式 SNS は削除されると直す作業が生まれる
- **ビルド時に画像を取得して保存**: Google の規約上できない

## 結果

- 外部サービス（Google）への依存と、閲覧者の IP が Google に送られることを受け入れた。プライバシーポリシーに明記する
- 全店に画像があるかは `npm run check:exterior`（無料の metadata API）で手で確かめる。定期実行はしない
- Google 以外に乗り換えるときは、`exterior.ts` と `ExteriorImage.tsx`、店舗データの `exterior` を差し替える
