# ADR 0004: 企画・要件定義書に沿って「ツギイエ」へ全面改修する

- 日付: 2026-10-09
- 状態: 採択（CLAUDE.md の「数を追わない」「味の評価とおすすめは扱わない」を置き換える。ADR 0001 の前提「定期作業・返信・締め切りを生まない」は維持する）

2026-10-08 の企画・要件定義書と基本設計書（外部設計）に沿い、系図を眺めるサイトから「訪問記録をもとに次の一杯を理由つきで提案する」サービスへ全面改修する。提案・訪問記録・味メモ・Google ログインを足すため、「数を追わない」「おすすめを扱わない」はそのままでは成り立たず、「数は測るが約束しない」「他人の評価は扱わない」に置き換える。一方、成功指標の達成や要件定義書の「誤りの報告に 7 日以内で対応」を約束すると返信義務と締め切りが生まれるため、ADR 0001 の前提は維持し、7 日以内は採らない。

同じリポジトリで段階的に置き換え（各段階の終わりでサイトが動く）、認証と DB は Firebase Spark、解析は GA4 を続ける。2026-10-09 に確かめた無料枠の一次情報が理由で、Supabase Free は 7 日無操作で停止して手動復元が要り、Vercel Web Analytics はカスタムイベントが Pro 限定、GA4 の Cookie なし運用は月 50 人規模ではレポートに数字が出ない。

## 設計書（docs/spec）からの変更点

着手時点で決めた、2026-10-08 の文書との食い違い。文書は凍結し、こちらを正とする。

- 系図の画面は `/keifu`「系譜」ではなく `/keizu`「系図」。CONTEXT.md の「系譜」（1 店から総本山までの経路）と衝突するため
- 「30 店に固定」は下限と読む。現 28 店（関東）を残し、愛知 10 店を足して 38 店にする
- 出典カード（PR #71）は廃止する。出典の画像 URL は任意項目として残し、写真は後で段階的に再導入する
- 設計書の（案）3 点は案どおり: 最終確認日が 1 年以上前なら注記を出す、ログアウトで端末の記録を消す、ダークモードは作らない
- 代表店は系統に順序つきで複数持つ（源流店で代用しない）。行ける店（閉店以外。本店閉店を含む）に限る。開拓の候補は総本山と資本系を除く 7 系統から選び、吉村家は直系の代表店の先頭に置く
- 確度は関係ごとの「確認済み／諸説あり」に一本化し、出典の種別から導く 3 段階（確定／報道による／未確認）は廃止する。出典ごとの種別表示は残す
- 関係は独立のレコードにし、1 店が複数の師匠への関係を持てる（諸説ありを 2 本で表す）。種類は 直系／修業して独立／インスパイア の 3 つで、「暖簾分け」「元直系」「影響」の語は使わない
- 最終確認日はサイト全体で 1 つではなく、店と関係のレコードごとに持つ
- 落とす旧機能: 年スライダーと再生、ホバーの点灯、縦書き、和風配色と 3 書体、検索欄、影絵の OGP、詳細パネル。流用するのは全体図の自動レイアウトとズームだけ
- 成功指標は GA4（Cookie あり）で測る。企画書 3 章と設計書 S-07 の「Cookie を使わない」は採らない
