ツギイエの初版は、下部タブ3つ (次の一杯・系譜・記録) と店ごとの個別ページを軸に、7画面と4つのシートで構成します。この文書は利用者から見える部分 (画面、遷移、表示項目、操作、文言) を定め、[企画・要件定義書](2026-10-08-requirements.md) の F-01〜F-12 をすべて画面に割り当てます。

## 1. 設計の決定事項

ヒアリングの12問はすべて決まりました。成果物は設計書のみとし、見た目の作り込みは実装時に行います。

| 項目 | 決定 |
| --- | --- |
| 成果物 | 設計書のみ (画面一覧、遷移図、ワイヤーフレーム、項目定義、文言) |
| ナビゲーション | 下部タブ3つ「次の一杯」「系譜」「記録」。ログインと固定ページは右上のメニュー |
| 系譜図 | 縦ツリーと全体図を切り替える。初期表示は縦ツリー。図を使わない一覧も用意する |
| 店の詳細 | 店ごとの個別ページ。店ごとにURLを持つ |
| 候補3店の選び方 | 深掘り・源流・開拓の3ルールから1店ずつ |
| 候補の入れ替え | 「別の候補」ボタンで3店をまとめて入れ替える |
| 記録の流れ | 「行った」を付けた直後に味メモを聞く。スキップでき、後から編集できる |
| 初回の体験 | 各系統の代表店を提案し、「行ったことのある店を登録する」導線を置く |
| ログインの案内 | 最初の記録の後に1回だけ表示する |
| 記録の統合 | ログイン時に端末内とアカウントの記録を自動で合算する |
| 外部リンク | 「地図アプリで開く」と「この店を共有」。出典と修正提案のリンクは必須 |
| トーン | 落ち着いた資料風。白基調で、色は系統の色分けに使う |

回答をもとに、次の4点を前提として置きました。違っていれば直します。

- 記録は1店につき1件とし、記録日には印を付けた日を自動で入れる。
- 表示言語は日本語のみとする。
- 推奨機能 (F-06、F-07、F-10) も画面に割り当てる。作らない場合に外す場所は10章に示す。
- 削除依頼の手順は「このサイトについて」に載せ、専用の画面は作らない。

## 5. 画面ごとの設計

各画面の表示項目と操作を定めます。未ログインでもすべての項目と操作を使えます。

### S-01 次の一杯

開くとすぐに候補3店が出ます。説明や登録の画面は挟みません。

| 表示項目 | 内容 |
| --- | --- |
| 都道府県の絞り込み | 初期値は「すべて」。選んだ値は端末に記憶する |
| 候補カード (3枚) | 切り口 (深掘り・源流・開拓)、店名、系統の色チップ、都道府県と市区町村、提案の理由 (一文)、行く理由 (2〜3文) |
| カード内のボタン | 「行った」「系譜で確かめる」 |
| 「別の候補」ボタン | 3枚の下に1つ置く |
| 初回の案内 | 記録が0件のときだけ表示する。「行ったことのある店を登録する」 |
| 提案の仕組み | 「どうやって選んでいる？」のリンク。S-06の提案ルールへ移動する |

- カードをタップすると、その店のS-03へ移動する。
- 「系譜で確かめる」は、その店を強調したS-02 (`/keifu?shop={店ID}`) へ移動する。
- 「行った」を押すとM-01が開き、閉じると候補が更新される。
- 「行ったことのある店を登録する」は、S-02の一覧表示へ移動する。

### S-02 系譜

提案の理由を確かめる場です。3つの表示は同じデータを見せ、絞り込みの条件を共有します。

| 表示 | 内容 | 操作 |
| --- | --- | --- |
| 縦ツリー (初期表示) | 系統ごとに折りたたむ。見出しに系統の色、名称、訪問済みの店数と全体の店数。開くと源流店から師弟関係を字下げで並べる | 見出しで開閉。店の行でS-03へ。系統名の横の「解説」でS-05へ |
| 全体図 | 全店を1枚の図にする。店は系統の色の丸、訪問済みは塗りつぶし。関係の種類は線の種類で分ける | 拡大、縮小、移動。店をタップすると画面下に店名と「詳細を見る」が出る |
| 一覧 | 図を使わない表。系統、店名、師匠筋と関係の種類、所在地、訪問済みの印 | 行でS-03へ。行の「行った」でその場で記録できる |

- 画面上部に、表示の切り替えと、系統・都道府県の絞り込み (F-06) を置く。
- 関係の線は、直系・暖簾分けを実線、修業して独立を破線、インスパイアを点線にする。線の凡例を図の下に常に表示する。
- 確度が「諸説あり」の関係には「諸説あり」の印を付け、タップでS-03の該当箇所へ移動する。
- `?shop={店ID}` が付いているときは、その店の系統を開き、店を強調して表示する。

### S-03 店の詳細

1店につき1ページです。上から「行く理由」「系譜上の関係」「出典」の順に並べ、記録の操作は画面下に固定します。

| 表示項目 | 内容 |
| --- | --- |
| 店名と系統 | 系統は色チップで示し、タップでS-05へ移動する |
| 営業状況 | 閉店または移転のときだけ表示する |
| 所在地と創業年 | 所在地は都道府県と市区町村まで |
| 行く理由 | 2〜3文。提案から来た場合は、提案の理由 (一文) を上に添える |
| 系譜上の関係 | 師匠筋と弟子筋を分けて並べる。1件ごとに相手の店、関係の種類、確度、出典 |
| 出典 | リンク先のサイト名とURL。諸説ある関係は両方の出典を並べる |
| 最終確認日 | 1年以上前の場合は「情報が古い可能性があります」を添える (案) |
| 記録 | 未訪問なら「行った」ボタン。訪問済みなら記録日、味メモ、「編集」「取り消す」 |
| リンク | 「地図アプリで開く」「この店を共有」「系譜で見る」「修正を提案する」 |

- 「地図アプリで開く」は、店名と市区町村でGoogleマップを検索する。住所や営業時間は自前で持たない。
- 「この店を共有」は端末の共有機能を開く。使えない端末ではURLをコピーする。
- 「修正を提案する」は、店IDと店名を入力済みにしたGitHubのIssue作成画面を新しいタブで開く。

### S-04 記録

自分の記録だけを見せる画面です。順位や連続記録は表示しません。

| 表示項目 | 内容 |
| --- | --- |
| 保存先の表示 | 未ログイン時は「記録はこの端末に保存されています」と「Googleでログイン」。ログイン中は「アカウントに保存されています」 |
| 全体の進み具合 | 訪問済みの店数と全体の店数 |
| 系統ごとの進み具合 (F-10) | 系統名、訪問済みの店数と全体の店数、横棒。演出は付けない |
| 訪問済みの店 | 店名、系統、記録日、濃さ、また行きたいか。新しい順 |

- 店の行をタップするとS-03へ移動する。行の「編集」でM-01が開く。
- 記録が0件のときは、空の状態の文言と「行ったことのある店を登録する」を表示する。

### S-05 系統の解説

系統の名称と色、源流店、初心者向けの解説 (3〜4文)、所属する店の一覧を表示します。店の行でS-03へ、「系譜で見る」でその系統を開いたS-02へ移動します。

### S-06 このサイトについて、S-07 プライバシーポリシー

| 画面 | 載せる内容 |
| --- | --- |
| S-06 | サービスの説明、提案ルール (3種類)、出典と諸説の扱い、ライセンス、修正の提案方法、掲載内容の削除依頼の手順、GitHubリポジトリへのリンク |
| S-07 | 保存する項目 (ログイン用の識別子、訪問記録、味メモ)、保存先のサービス名、削除方法、Cookieを使わないアクセス解析の説明、連絡先 |

### M-03 メニュー

未ログイン時は「Googleでログイン」、ログイン中は「ログアウト」と「アカウントを削除」を表示します。その下にS-06、S-07、GitHubへのリンクを置きます。表示名とメールアドレスは扱わないため、ログイン中の表示は「ログイン中」の文字だけです。M-01、M-02、M-04は7章で定めます。

## 6. 提案の表示ルール

候補は3つの枠 (深掘り・源流・開拓) に1店ずつ出し、同じ記録からは必ず同じ候補が出ます。乱数は使いません。利用者が「なぜこの店か」を自分で確かめられるようにするためです。

対象は、都道府県の絞り込みに合い、未訪問で、営業中の店です。

| 枠 | 候補になる店 | 並べる順 | 理由の一文 (ひな形) |
| --- | --- | --- | --- |
| 深掘り | 訪問済みの店と同じ系統の店 | 「また行きたい」を付けた店と同じ系統が先。次に訪問済みの店と直接の関係がある店 | 訪問済みの{A店}と同じ{系統名}。 |
| 源流 | 訪問済みの店の師匠筋にあたる店 | 「また行きたい」を付けた店の師匠筋が先。次に直接の師匠、その上の順 | {A店}の店主が修業した店。{A店}の味の原点を確かめられる。 |
| 開拓 | まだ1店も行っていない系統の代表店 | 店数の多い系統が先 | まだ行っていない{系統名}の代表店。 |

- 同じ順位の店は店IDの順に並べる。
- 同じ店を2つの枠に出さない。先に深掘り、次に源流、最後に開拓の順で決める。
- 候補のない枠は、開拓、深掘り、源流の順に、ほかの枠の次点で埋める。埋めた枠には元の切り口の名前を表示する。
- 「また行きたい」が理由になったときは、理由の一文を「『また行きたい』を付けた{A店}と同じ{系統名}。」に替える。
- 源流の一文は関係の種類で替える。直系・暖簾分けは「{A店}の本店筋にあたる店。」、インスパイアは「{A店}が手本にした店。」とする。

場面ごとのふるまいは次のとおりです。

| 場面 | ふるまい |
| --- | --- |
| 記録が0件 | 店数の多い系統から順に、代表店を3店出す。切り口の表示は「代表店」、理由は「{系統名}の代表店。」 |
| 「別の候補」を押す | 3つの枠をそれぞれ次点に進める。次点のない枠はそのまま残す |
| 次点が尽きた | 最初の3店に戻り、「候補を一巡しました」と表示する |
| 記録または絞り込みを変えた | 候補を作り直し、先頭から表示する |
| 候補が1〜2店しかない | 出せる店だけを表示し、絞り込みを外す案内を添える |
| 候補が0店 | 絞り込み中は「この地域の店はすべて訪問済みです」、全国では「全店を訪問済みです」と表示する |

## 7. 記録とログインのふるまい

記録は「行った」を押した時点で保存し、味メモは任意です。ログインの有無で変わるのは保存先だけで、画面と操作は同じです。

### 記録と味メモ (M-01)

M-01は画面の下から出るシートです。

| 項目 | 内容 |
| --- | --- |
| 店名 | 記録した店の名前 |
| 濃さ | 濃い・普通・あっさりから1つ。選ばなくてもよい |
| また行きたい | はい・いいえ。選ばなくてもよい |
| ボタン | 「保存」「あとで」 |

1. 「行った」を押すと、当日を記録日として保存し、M-01を開く。
2. 「保存」で味メモを保存して閉じる。「あとで」またはシートの外をタップすると、印だけ残して閉じる。
3. 閉じた後、「{店名}を記録しました」と数秒表示する。
4. 味メモはS-03またはS-04の「編集」からいつでも変えられる。
5. S-03の「取り消す」は確認を出してから、その店の記録と味メモを消す。

S-02の一覧で続けて登録するときは、次の店の「行った」を押すと前の店のM-01が閉じ、次の店のM-01に替わります。

### ログイン (M-02、M-03)

| 場面 | ふるまい |
| --- | --- |
| ログインの案内 (M-02) | 未ログインで最初の記録を付け、M-01を閉じた後に1回だけ出す。「Googleでログイン」「今はしない」。どちらを選んでも二度と出さない |
| ログインする | Googleの画面へ移動し、終わると元の画面に戻る |
| 記録の合算 | 端末内とアカウントの記録をすべて残す。同じ店が両方にあれば、後から更新した方の味メモを使う。確認は出さない |
| 合算の結果 | 端末内に記録があった場合だけ「この端末の記録{n}件をアカウントに保存しました」と表示する |
| ログアウトする | 確認を出す。ログアウト後はこの端末に記録を残さず、0件の状態に戻る (案) |
| 保存に失敗した | 画面の表示は変えず、「保存できませんでした。接続を確かめてもう一度お試しください」と表示する |

### アカウントの削除 (M-04)

1. メニューの「アカウントを削除」を押すと、M-04が開く。
2. M-04に「アカウントと訪問記録、味メモをすべて削除します。元に戻せません。」と表示する。ボタンは「削除する」「やめる」。
3. 「削除する」を押すと、サーバーとこの端末の記録を消し、未ログインの状態でS-01へ移動する。
4. 「アカウントを削除しました」と表示する。

## 8. 文言とメッセージ

文言は「です・ます」調で短く書き、食べる頻度を煽る表現 (「あと◯店で制覇」「今週の目標」など) は使いません (N-11)。6章と7章で定めた文言もここに集め、実装時はこの表を正とします。

| ID | 画面 | 場面 | 文言 |
| --- | --- | --- | --- |
| T-01 | S-01 | 記録が0件のときの見出し | まずは各系統の代表店から。 |
| T-02 | S-01 | 初回の案内 | 行ったことのある店を登録すると、あなたに合わせた候補に変わります。 |
| T-03 | S-01 | 候補を一巡した | 候補を一巡しました。最初の3店に戻ります。 |
| T-04 | S-01 | 候補が1〜2店 | この地域の候補はこれで全部です。絞り込みを外すと、ほかの地域の店も出ます。 |
| T-05 | S-01 | 絞り込み中に候補が0店 | この地域の店はすべて訪問済みです。 |
| T-06 | S-01 | 全国で候補が0店 | 全店を訪問済みです。新しい店の追加をお待ちください。 |
| T-07 | S-02 | 絞り込みの結果が0店 | 条件に合う店がありません。 |
| T-08 | S-02、S-03 | 諸説ある関係 | 諸説あり。両方の出典を載せています。 |
| T-09 | S-03 | 最終確認日が1年以上前 | 情報が古い可能性があります。 |

## 9. 表示の方針

見た目は白基調の資料風とし、色は系統の色分けと操作できる要素にだけ使います。出典と理由を落ち着いて読めることを優先します。

| 項目 | 方針 |
| --- | --- |
| 配色 | 背景は白、文字は濃いグレー。リンクとボタンは1色に統一する。それ以外の色は系統の色分けだけに使う |
| 系統の色 | 色だけで区別させない。系統名を必ず文字で添える。訪問済みは塗りつぶしとチェック印の両方で示す |
| 文字 | 端末の標準書体を使う。本文は16px以上、行間は1.7前後 |
| 写真と装飾 | 写真、イラスト、動きのある演出は使わない |
| 操作の大きさ | ボタンと行のタップ領域は44px四方以上 |
| スマートフォン | 幅360pxから崩れない。片手で届くよう、主要な操作は画面の下側に置く |
| PC | 幅768px以上では下部タブをヘッダーに移す。S-02は図の横に店の要約を並べる |
| ダークモード | 初版では作らない (案) |
| 外部リンク | 出典、地図、GitHubは新しいタブで開き、外部へのリンクであることを印で示す |
| アクセシビリティ | S-02は一覧表示だけですべての情報を読める (N-10)。キーボードだけで操作できる。文字と背景のコントラスト比は4.5:1以上 |
| 表示の速さ | S-01は候補3店の文章を最初に表示する。全体図は、その表示を開いたときに読み込む (N-05) |
| 対応ブラウザ | iPhoneのSafari、AndroidのChrome、PCのChrome・Edge・Safari・Firefoxの最新版 (N-06) |

F-01〜F-12はすべて画面に割り当て済みです。

| F-04 | 次の一杯の提案 | 必須 | S-01 |
| F-05 | 修正の提案導線 | 必須 | S-03、S-06 |
| F-06 | 絞り込み | 推奨 | S-02 |

日程が遅れた場合に外す場所は次のとおりです。

この設計で、要件定義書のデータ項目に3つの追加が必要になりました。

- 訪問記録に更新日時を足す。合算で「後から更新した方」を選ぶために使う。
- 系統に表示用の色を足す。
- 開拓の枠で使う「代表店」を決める。系統の源流店をそのまま使うか、項目を足すかを内部設計で決める。

設計書の中で案として置いた点は3つです。確認をお願いします。

- [ ] 最終確認日が1年以上前の店に「情報が古い可能性があります」を出す。
- [ ] ログアウトすると、この端末には記録を残さない。
- [ ] ダークモードは初版では作らない。

内部設計で決めることは次のとおりです。

- [ ] 静的サイト生成、ホスティング、認証とデータベースのサービスを選ぶ。
- [ ] 全体図の描画ライブラリを選び、スマートフォンで30店の図が滑らかに動くか確かめる。
- [ ] 端末内に保存する項目 (記録、都道府県の選択、M-02を出したか) の形式を決める。
- [ ] 系譜データ (店、関係、系統) のファイル形式と自動検証の規則を決める。
- [ ] GitHubのIssueテンプレートを作る。
- [ ] 成功指標の計測点を決める。S-01のカードからS-03へ移動した数を数える。
